## 为什么是仪表盘而不是长文档

用户要在十几个候选之间反复比较、换口径重排、挑一个深挖。长文档只能从头读到尾，比较成本高。仪表盘把「看全貌」「看单个」「改口径」拆成独立视图，左侧导航常驻，随时切换。

呼吸感是硬要求，不是审美偏好。卡片之间 20px 间距、卡片内 24 到 26px 内边距、20px 圆角、暖灰画布托白卡，这套留白让密集的技术信息可读。把间距压到 8px 会让整页变成一堵墙，用户第一屏就放弃。

## 设计语言

配色从主题推导，不是通用灰蓝。六个维度各占一色，图表、雷达图、打分依据的色点、权重滑块共用同一套映射：

| 维度 | 色值 | 用在哪 |
|---|---|---|
| AI 核心技术占比 | `#2563eb` 蓝 | 主色，瀑布图首段、实心总分条、A 档柱 |
| 新颖性 | `#7c3aed` 紫 | 瀑布图第二段、雷达轴 |
| 时效性 | `#0891b2` 青 | 待核实图标 |
| 上手难度 | `#059669` 绿 | 项目解法卡、A 档徽标 |
| Star | `#f59e0b` 琥珀 | 风险条、教程化标签 |
| 业务真实性 | `#db2777` 玫红 | 难点卡、淘汰区 |

中性色分四层：画布 `#f4f3f1`、卡面 `#fff`、次级面 `#faf9f7`、描边 `#e9e6e1`。文字三级 `#0f0e0d` / `#5b5651` / `#9a938b`。遮罩 `rgba(20,18,16,.42)`。

图表用斜纹填充区分「未达标」和实心「已达标」，这是从参考风格里继承的语言：分布图里 A 档实心蓝、其余斜纹浅蓝；瀑布图每段按维度色斜纹，最后总分实心蓝。斜纹让色盲用户也能分辨，不依赖颜色单一通道。

渐变洞察卡跑蓝到紫到橙三个色相，叠三层 radial-gradient 加一层线性底，右下角一个旋转的圆角方框做装饰。这是整页唯一的强饱和区域，用来承载「需要你知道的判断」，不要给别的卡片也加渐变，否则失去焦点。

滚动条必须自己画：11px 宽、`#f1eee7` 轨道、`#cfc9c1` 滑块带 3px 同色描边、hover 变浅蓝、active 变主蓝。表格横向滚动条单独调成 9px。浏览器默认滚动条会破坏整体质感。

## 布局与响应式

栅格 12 列，卡片用 `.c4` `.c5` `.c6` `.c7` `.c8` `.c12` 占位。三个断点：

- **> 1240px**：三栏。总览是 KPI + 瀑布图 + 渐变卡并排，下面分布图占 8 列、待办占 4 列。
- **1080 到 1240px**：`.c4` `.c5` 降为 6 列，`.c7` `.c8` 降为 12 列，变两栏。
- **< 1080px**：侧栏变抽屉，`transform:translateX(-102%)` 移出屏幕，顶栏出现汉堡按钮，展开时铺遮罩。点遮罩或按 Esc 关闭，选完导航自动关闭。
- **< 820px**：所有卡片满宽，难点与解法对照从左右分栏堆叠成上下，打分依据从两列变一列。

表格永远包在 `.tw` 里横向滚动，不让它撑破页面。这一条在 390px 下尤其重要：表格内容宽 815px，容器 293px，靠容器内滚动消化。

## 六个视图

| 视图 | 内容 |
|---|---|
| 总览 | 主推 KPI 加斜纹进度条、总分构成瀑布图、渐变洞察卡（三条轮播）、候选分布柱状图、需要你拍板、求职坐标、后续可选链路 |
| 候选详情 | 筛选栏 + 打分表 + 每个候选的完整卡片 |
| 难点与解法 | 把全部候选的难点解法对照聚合，按候选分组，可跳回完整卡片 |
| 权重控制台 | 六个滑块 + 两个档位开关 + 五个动作按钮 + 实时排序预览 |
| 淘汰区 | 淘汰原因列表 |
| 待核实 | 未核实项列表 |

候选卡片顺序固定：一句话简介 → 立项动机 → 难点与项目解法 → 核心技术方格 → 风险 → 信号标签 → 折叠的打分依据 → 折叠的上手路径。简介必须在立项动机之前，读者先知道这是什么才有耐心听为什么。

## 交互契约

这些都是实装的，改模板时不要弄坏：

- **⌘K / Ctrl+K** 聚焦搜索框。搜索实时过滤，在总览等视图输入会自动跳到候选详情。
- **筛选**：平台（全平台 / GitHub / Gitee）、类型（全部 / 能跑起来 / 读源码）、档位（全档 / A / B / watch）。
- **排序**：总分、AI 占比、star、最近更新、仓库名。表头也可点击排序。
- **表格行点击**跳到对应候选卡片并短暂高亮描边。
- **六个权重滑块**：0 到 50，步进 5，`input` 事件即时重算总分、档位、排序、预览表和顶栏 A 档计数。合计不等于 100 时提示按占比归一化，不报错。
- **两个开关**：业务真实性硬准入默认**开**，教程化一票降档默认**关**。这是用户明确的口径，不要改默认值。
- **五个动作**：恢复默认（35/10/15/15/10/15）、随机一组、六维等权、技术优先（45/10/15/15/5/10）、导出当前权重下的 JSON。
- **导出**下载 `job-project-report-adjusted.json`，含重算后的 total 与 tier，`meta.weight_note` 写明导出时的权重和两个开关状态。
- **渐变卡**三条洞察 7.6 秒轮播，鼠标悬停暂停，圆点可手动切换。
- **反馈**：动作后弹底部 toast，2 秒消失。
- `prefers-reduced-motion` 下所有动画与过渡降到 0.01ms。

## 数据契约里容易漏的字段

完整结构在模板顶部注释。这几个容易漏，漏了不报错但报告会缺信息：

**`tutorial_heavy`（布尔，可选）**。教程化降档开关依赖它。缺省时模板从 `risks` 按固定词表推断：「教程化严重」「教程化极重」为 true，「教程化中等」「教程化低」「教程化轻」「无明显教程」为 false。词表外的措辞（如「教程化程度较高」）推断不出来，开关静默失效。渲染脚本会拦住词表外的写法，要么改词要么显式给布尔值。

**`platform`（`github` 或 `gitee`，缺省 github）**。决定来源列的标签、平台筛选器分组、总览的 GitHub / Gitee 统计行。渲染脚本会校验 url 域名与 platform 一致，且不带 `.git` 后缀（Gitee 的 `html_url` 原样搬过来会点不开）。

**`skeleton`（可选但强烈建议）**。项目骨架示意图。结构是 `{lanes:[{label, nodes:[{name, note}]}], caption, basis}`，2 到 5 条泳道，每条至少一个节点。渲染成横向方格加箭头，窄屏自动竖排且箭头旋转 90 度。`name` 用真实目录或文件路径，`basis` 写清依据来自哪次 probe 的哪些字段，渲染脚本会强制校验这两项。用 HTML 弹性盒子而不是 SVG，是为了窄屏能重排且字号不缩水。

**`product_form`（`product` / `library` / `infra` / `unknown`，缺省 product）**。库和引擎会被渲染脚本拦下，不允许留在候选里。`unknown` 会在卡片元信息行显示琥珀色「形态待确认」标签，提醒人工读 README 定。判定细则见 `scoring.md` 的产品形态硬门槛。

**`gvp`、`renamed_from`**。Gitee 特有。前者显示绿色 GVP 标签，后者显示琥珀色「原名 xxx」标签。改名很常见，Gitee 会静默把 `chatgpt-on-wechat` 解析成 `CowAgent`，不标原名用户会以为是两个项目。

**`stars_per_month`、`days_since_push`、`releases_90d`**。probe 已经算好，直接搬进报告 JSON。候选卡片的元信息行会显示月增速，漏了显示破折号。

**`signals`**。probe 的结构信号原样带上，渲染成卡片底部的红色标签。`ai_band_divergence` 是用户复核 AI 占比的入口，不要丢。

**`verified`**。false 时卡片标题旁出现「未完全核实」标签。

**`track`**。只能是 `runnable` 或 `source-reading`，决定筛选分组和折叠区标题是「上手路径」还是「阅读路径」。

## 验收playbook

渲染完必须实际打开跑一遍，不能只看文件写成功。

**1. 打开与控制台**。用浏览器工具导航到 `file://` 绝对路径（中文路径要 URL 编码）。先查控制台消息，必须为空。页面顶部若出现红色 banner，说明 JSON 没注入成功或格式坏了。

**2. 溢出与裁切**。用脚本量，不要靠肉眼：

```js
document.body.scrollWidth <= window.innerWidth + 2
[...document.querySelectorAll('.cell,.tc,.summary,.pitch')]
  .filter(e => e.scrollWidth > e.clientWidth + 1).length === 0
```

**3. 对比度**。取计算样式算相对亮度比，正文与标签都要 ≥ 4.5。当前实测难点正文 9.15、解法正文 9.12、渐变卡白字 5.17。

**4. 控件逐个点**。六个滑块改值后确认总分和预览表变了；两个开关切换后确认 A 档数量变了；五个动作按钮各点一次；搜索输一个仓库名确认条数收敛；表头排序和行点击跳转各测一次。

**5. 导出**。不要真下载到 Downloads。临时替换 `URL.createObjectURL` 捕获 Blob、替换 `HTMLAnchorElement.prototype.click` 阻止下载，读 Blob 文本解析 JSON，核对 weights、每个候选的 tier 与 total、`funnel.recommended`，测完还原两个函数。

**6. 监听器泄漏**。包装 `addEventListener` / `removeEventListener` 计数，连续切八次视图，`scroll` 监听应增删相等净 0。

**7. 响应式**。内置浏览器的视口宽度不可控，用 iframe 夹具精确测：写一个临时 HTML 放一个 iframe 指向报告，改 `iframe.style.width` 到 390 / 768 / 1024 / 1440，每次等 300ms 再进 `contentDocument` 量。检查侧栏位置、汉堡按钮 display、难点对照的列数、表格是否在容器内滚动、有无元素右边界超出视口。

**8. 截图**。能截就截，看整体观感。内置浏览器面板隐藏时截图会失败，这时改用几何测量并如实说明「这一轮是结构验证不是看图」，不要声称看过。

## 渲染架构与防闪刷

**外壳只建一次，之后只换 `.content` 的内容。** 这条是硬约束，改模板时最容易破坏它。

早期版本每次状态变化都执行 `app.innerHTML = sidebar() + topbar() + body()`，把整页 DOM 重写一遍。后果是持续闪刷：

- `.card` 和 `.cand` 的入场动画 `animation:rise` 每次重建都重放，整页卡片重新淡入上浮
- `window.scrollTo(0,y)` 在重建后恢复滚动，视觉上跳一下
- 搜索框在侧栏里，跟着一起重建，每敲一个字就丢焦点再抢回来
- 折叠区展开状态丢失
- 总览的洞察卡有 7.6 秒轮播定时器，它调用同一个全量 render，于是**什么都不点也在闪**

现在的做法：

| 机制 | 实现 |
|---|---|
| 外壳只建一次 | `SHELL` 标志，`bindShell()` 只绑一次；侧栏与顶栏永不重建 |
| 内容区单独更新 | `render(opts)` 只写 `#content.innerHTML`，`bindContent()` 重绑内容区 |
| 外壳增量补丁 | `patchShell()` 改导航高亮、计数、标题、A 档 chip；值相同就不写，避免无谓的文本节点churn |
| 入场动画只在切视图时播 | `.content.anim` 类控制，`animation` 默认 `none`；筛选、排序、搜索、开关都不加这个类 |
| 轮播只切 class | 三条洞察一次性全渲染进 `#heroSlides`，叠在同一网格单元，`setHero(i)` 只切 `.on`；容器高度自动取最高一条，切换不跳高 |
| 搜索防抖且不动侧栏 | 160ms 防抖，只更新内容区，焦点与光标天然保持，不需要手动 `focus()` 抢回 |
| 折叠状态跨渲染保留 | `OPEN_FOLDS` 按 `卡片id|标题` 记录，`restoreFolds()` 重放 |
| 数字动画只在切视图时跑 | `animate(withMotion)`，补丁更新直接落终值 |
| 后台不轮播 | 定时器检查 `document.visibilityState`，隐藏时跳过 |

验收方法：用 `MutationObserver` 观察 `#app` 的 `childList`，分别统计落在 `#content` 和 `#side` 上的次数。

- 点三次洞察圆点：`#content` 重建 **0** 次，`#side` **0** 次，`.slide` 的 class 变更 6 次
- 搜索输入一次：`#side` **0** 次，`#content` **1** 次，`document.activeElement` 仍是输入框
- 点筛选器：`#content` 的 class 不含 `anim`
- 切视图：class 含 `anim`

任何一条不达标就是闪刷回归了。

## 已经踩过的坑

**占位符只能出现一次**。模板里 `__REPORT_DATA__` 出现两次时，Python 的 `replace` 会把 JSON 也注入到 JS 字符串里，产出白屏页。渲染脚本现在会校验次数必须为 1，且只替换第一处。

**隐藏页面里 CSS 过渡不推进**。`visibilityState` 为 hidden 时读 `getComputedStyle(el).transform` 会拿到过渡起始值，看起来像抽屉坏了。测抽屉位置前先注入 `.side{transition:none!important}`，量完移除。实测闭合态 x=-275、展开态 x=0 才是对的。

**雷达图 viewBox 要留标签宽度**。六轴左右两侧的中文标签会超出 viewBox 被裁。当前用 236×200 的 viewBox 配 cx=118、R=60、标签偏移 R+18，实测无裁切。改轴数或标签文案后要用 `getBBox()` 重新验。

**固定 min-width 会撑破窄屏**。弹性子项用 `flex:1 1 260px;min-width:0` 而不是 `min-width:260px`，否则 390px 下溢出。

**闭合的 details 会残留宽屏布局**。原生 `<details>` 闭合时子树是 `content-visibility:hidden`，窗口缩窄后不重新布局，`getBoundingClientRect` 仍返回宽屏时的宽度，并把整页撑出横向滚动。所以折叠区改用按钮加 `hidden` 属性，`display:none` 的子树没有几何尺寸，不会残留。

**mono 长路径没有断行点**。骨架的依据行、模块路径、元信息行都是长串，窄屏会撑破容器并向上传导。给这些容器加 `overflow-wrap:anywhere`。实测 `.skel-basis` 一行在 390px 下撑出 93px，最终让整页溢出 52px。

**表格必须包滚动容器**。直接放 `<table>` 会让整页横向溢出，包 `.tw{overflow-x:auto}` 才是容器内滚动。
